# Newsletter bug audit and release checks

User request: audit all of Mike's newsletter feedback, fix bugs, and merge the work.
This audit follows the original implementation in PR #246.

## Bugs corrected

- Hidden and segment-restricted Preview Text could leak into the inbox preheader. The fallback now applies the same visibility and audience filter as the delivered body.
- Server normalization treated deliberately empty modern fields as missing and resurrected old titles, body text or links. Only absent modern fields use legacy fallbacks.
- Empty headers could send the editor's Logo placeholder. Placeholder logos are no longer delivered. Explicit logo sizing is distinct from legacy 40px defaults.
- Zero block gaps and mobile padding overrides could be overridden by fixed CSS. Shared spacing now respects the configured values.
- New block types did not inherit the account's role-specific fonts. Branding fallback now matches the existing blocks without resetting layout-specific typography.
- Product gallery description, original-price and border switches were ignored or missing from the simplified controls. Rendering and controls now preserve those choices.
- Explicit product image placement could lose to an old layout preset. The explicit selection now wins.
- Button-link decoration accepted an unvalidated string into generated attributes. It now accepts only the supported decoration choices.
- Coupon imports dropped badges; unsupported offer names silently became prices. Badges are preserved and unsupported offers require a correction before insertion.
- Wide data tables accepted columns that the renderer would silently drop. Imports above 12 columns now explain how to split the table.
- Invalid replacement imports could leave old rows enabled for insertion. Closed/reopened dialogs could accept late file/feed results. Reads now invalidate earlier results and clear stale rows.
- A slow image upload could overwrite newer captions/reordering, restore deleted slots or update an unmounted block. Upload completion now resolves the latest block and stable gallery item ID.
- Generated coupon barcodes and social icons were exposed as ordinary photo-upload targets. They are now read-only in the canvas.
- Browser-library imports could continue after an account change. Each write is bound to the explicitly confirmed account, remaining records are retained on interruption, and pending save dialogs close on account changes.
- Saved JSON could contain malformed gallery values that crashed rendering. Nested values and UTF-8 payload size are validated before reuse.
- Clearing an individual appearance control behaved differently before and after saving. Undefined overrides now inherit the master value consistently.
- Conditional segments that included all customers or evaluated rules did not consistently enforce store location scopes. Primary-location/activity evidence and selected-location targets now constrain every match.
- The preview endpoint authenticated the caller but did not authorize a requested tenant/campaign/recipient before privileged data reads. Campaign permissions and JWT-scoped, tenant-bound lookups now run first.
- Tracking URL discovery could omit URLs in conditional variants not visible to a representative recipient. Discovery includes all variants; actual sends still resolve each recipient's allowed blocks.

## Validation evidence

- Full application suite: **2,090 passed, four skipped** (295 passing files, one skipped).
- Focused newsletter/editor suite: **138 passed**.
- Deno recipient/tenant/location behavioral tests: **10 passed**. These tests mock database responses and do not send email.
- Six Chromium rendering cases: 640px and 700px designs at 375px, 480px and 900px viewports. No script errors or horizontal document overflow.
- Production build completed. Existing repository-wide type issues are evaluated separately from newly introduced diagnostics.
- Regression tests cover cleared content, preheader isolation, import replacement/cancellation, upload races, account changes, malformed saved data, preview authorization and location-specific audiences.
